# 西南林业大学（SWFU）统一身份认证扩展

API v3 新正方扩展（`kind: extension`，`extends: builtin.zf`），当前版本 **1.1.9**。

- 认证：在 App 内用**学号 + 统一身份认证密码（个人门户密码）**登录学校正方定制 CAS
  （倒序 RSA、图片验证码；二次认证时交接官方网页），登录后核验姓名与学号。
- 校历作息：`study.calendar` 调用学校「按周次课表」的接口，返回**真实的 12 节次起止时间
  和开学日期**，修正 App 默认节次时间；学期、课表、成绩、考试与选课继续复用内置新正方协议。

> **2026-11-16 起，学校关闭了教务本地密码通道**：`POST /jwglxt/xtgl/login_slogin.html`
> 一律 302 到统一认证，旧的教务系统密码不能再登录。1.1.6 改为只走 CAS，
> 请填「统一身份认证密码」。

## 1.1.9：入口异常页面继续重试

真机（1.1.8）显示：IPv6 回退成功后拿到的 200 页面不含登录表单，插件直接报「表单发生变化」。
1.1.9 在入口阶段校验页面确有可提交的 `#fm1`（execution），没有就继续重试；宿主选择器解析失败时用正则兜底；
仍失败时错误信息带页面提示文字。

## 1.1.8：5xx 重试 + 报错标注阶段

真机 3 次失败诊断（插件 1.1.7）：每次登录都在某次新建连接上先等约 20.4–20.7 秒（IPv6 不可达），
回退 IPv4 成功后紧接着的请求失败；1.1.7 对「提交登录返回 5xx」不重试，整次登录在约 21 秒处失败。

1.1.8：把 5xx 纳入重试（最多 3 次），并把网络错误标注到具体阶段（入口 / 公钥 / 验证码 / 提交 / 核验），
另加离线用例「登录提交遇到 502 后自动重试成功」。

## 1.1.7：修 IPv6 回退后旧连接导致的误报

真机诊断（App 1.0.135 / 插件 1.1.6，2026-11-16 08:28）显示：`cas.swfu.edu.cn` 同时解析到不可达的 IPv6
`2001:250:280d::216`，宿主的 OkHttp 会先连 IPv6、约 20 秒超时后在**同一个请求内**回退 IPv4 并成功；
但紧接着的下一个请求偶尔命中已关闭的旧连接而立即失败，1.1.6 把这种瞬时失败误报成「入口发生变化」。

1.1.7 的修复：

- 公钥、验证码状态、验证码图片、登录提交都加一次**瞬时断连重试**（业务错误不重试）；
- 网络失败单独提示：「再点一次密码登录」；通常第二次会直接走已缓存的 IPv4 路由，明显更快；
- 新增离线用例「公钥接口偶发断连后自动重试成功」。

## 1.1.6：学校关闭本地登录，改为纯 CAS + 入口重试

- 学校已关闭教务本地密码通道（1.1.4/1.1.5 的「教务密码本地直登」失效）；
  `POST xtgl/login_slogin.html` 直接 302，不再校验 `yhm`/`mm`。
- 教务域名前置负载均衡按 `route` Cookie 粘后端节点，**只有部分节点部署 `/sso/zfiotlogin`**
  （其余 404 空响应）。没有 `route` Cookie 时反复请求会重新随机落点（实测平均约 3 次命中）。
  1.1.6 把 `/sso` 入口重试提高到 **10 次**（失败概率降到约 2% 以下）。
- 顺序很关键：先访问 `/jwglxt/...` 会写死 `route` Cookie，若该节点没有 `/sso`，之后重试全是 404。
  所以登录入口是本轮登录的**第一个**请求，入口阶段不碰 `/jwglxt`。
- 密码被拒时明确提示：要填「统一身份认证密码」，不是旧教务密码；
  入口 10 次都不可用时提示稍后重试或改用「Cookie 登录 / 内嵌浏览器自动获取」；
  423 风控锁定仍保留 30 分钟提示。

## 1.1.5：兜底与错误提示（本地直登部分已被学校关闭）

- 优先教务密码本地直登；失败后回退统一认证，入口在「本地登录页 ↔ /sso」之间重试 3 轮。
- 登录失败区分「教务密码 / 统一认证密码」；本地被拒且 CAS 入口不可用时提示改用网页/Cookie 登录。
- 423 风控锁定保留原有 30 分钟提示。

> 学校已于 2026-11-16 关闭本地密码接口，这一版的本地直登分支在 1.1.6 中已移除。

## 1.1.4：教务密码本地直登（绕过统一认证网络问题）

2026-11-16 学校把教务登录强制 302 到统一认证，同时 `/sso/zfiotlogin` 部分后端节点随机 404；
另外 `cas.swfu.edu.cn` 公网 IPv6 不可达，App 直连 CAS 会先等 20 秒 IPv6 超时，超过宿主登录超时。

当时实测发现：教务前端虽然强制跳 CAS，但后端 `/jwglxt/xtgl/login_slogin.html` 的本地账号密码 POST 仍可用
（`yhm` + `mm` 明文，约 2 秒建会话，只走 IPv4 的教务域名）。1.1.4 因此改为：

1. 先尝试教务本地密码直登（单请求、IPv4、约 2 秒）；
2. 本地被拒或接口关闭时，回退统一身份认证 CAS（倒序 RSA、验证码）；
3. 统一认证入口在 `/jwglxt/xtgl/login_slogin.html` 与 `/sso/zfiotlogin` 间重试，避开 /sso 的 404 抖动。

## 1.1.3：登录入口变更修复

2026-11-13 学校把 `/jwglxt/xtgl/login_slogin.html` 改成**本地密码表单（200，不再 302 到统一认证）**，
1.1.2 从该地址进入会报 `PAGE_CHANGED`。1.1.3 认证入口改为直接访问 `/sso/zfiotlogin`（仍 302 到 CAS，
登录成功后回跳教务建立会话），密码、验证码、二次认证交接逻辑不变。

同日实测：逐周（1-20 周）单周课表并集 23 条，与学期课表 23 条完全一致，无遗漏。

## 1.1.2：作息获取改为并行

宿主单次插件调用只有约 5 秒预算，原实现「周次 → 整份课表取校区号 → 节次」串行三次请求容易超时，
超时后 `study.calendar` 被静默丢弃、课表退回 App 默认 08:00。1.1.2 改为「周次 + 节次」并行，
校区号默认 1，并在节次接口不可用时用学校公开作息兜底。

## 1.1.1：风控锁定转人工登录

学校统一认证在多次失败后会返回 **HTTP 423**，短信提示「账号登录异常，已被锁定，30 分钟后自动解锁」。
1.1.1 起把 423 映射为「需要人工登录」（`WEB_LOGIN_REQUIRED`），宿主不会在锁定期内自动续登反复撞锁。

## 重新构建

开发套件：`plugin-starter-v3.zip`（SDK 3.11.1 / API v3），解压到**非 /sdcard 文件系统**后：

```sh
npm ci
cp -r <this-repo> plugins/swfu-sso
npm run plugin -- check swfu-sso
npm run plugin -- test swfu-sso
npm run plugin -- submit-check swfu-sso
npm run plugin -- pack swfu-sso
npm run plugin -- source-zip swfu-sso
```
